9. Join Topology: New v_psa_stg_price_availability Pattern

The following is the recommended CTE structure for rewriting the 6 v_psa_stg_price_availability__profitero_* files. This pattern resolves all surrogate keys back to natural IDs and handles the 2 lost columns.

---- SRC LAYER ----
WITH
SRC_S    AS (SELECT * FROM {{ source('profitero_share_fiberon', 'DIM_PRODUCT_HISTORY') }}),
SRC_DD   AS (SELECT DIM_DATE_KEY, DT_DATE
             FROM {{ source('profitero_share_fiberon', 'DIM_DATE') }}),
SRC_AP   AS (SELECT DIM_ACCOUNT_PRODUCT_KEY, ACCOUNT_PRODUCT_ID AS CUSTOMER_PRODUCT_ID
             FROM {{ source('profitero_share_fiberon', 'DIM_ACCOUNT_PRODUCT') }}
             QUALIFY ROW_NUMBER() OVER(PARTITION BY DIM_ACCOUNT_PRODUCT_KEY ORDER BY PSA_LOAD_DTS DESC)=1),
SRC_R    AS (SELECT DIM_RETAILER_KEY, RETAILER_NAME AS NAME
             FROM {{ source('profitero_share_fiberon', 'DIM_RETAILER') }}
             WHERE PSA_DELETE_IND = 'N'
             QUALIFY ROW_NUMBER() OVER(PARTITION BY DIM_RETAILER_KEY ORDER BY PSA_LOAD_DTS DESC)=1),
SRC_A    AS (SELECT BKCC, REC_SRC FROM {{ ref('ref_business_key_collision') }})

---- LOGIC LAYER ----
, LOGIC_S AS (
    SELECT
        COALESCE(NULLIF(TRIM(ap.CUSTOMER_PRODUCT_ID::VARCHAR),''),'-1') AS PRODUCT_BK
      , CONVERT_TIMEZONE('UTC', IFF(s.PSA_DELETE_IND='Y', s.PSA_LOAD_DTS, s.UPDATED_AT)) AS LOAD_DTS
      , dd.DT_DATE                           AS DATE
      , ap.CUSTOMER_PRODUCT_ID              AS CUSTOMER_PRODUCT_ID
      , s.DIM_RETAILER_KEY::VARCHAR          AS RETAILER_ID          -- surrogate now
      , s.DIM_RETAILER_PRODUCT_KEY::VARCHAR  AS PRODUCT_ID           -- competitor product key
      , s.UPDATED_AT
      , s.AVAILABILITY
      , s.REGULAR_PRICE
      , s.PROMOTION_TEXT
      , s.PROMOTION_PRICE
      , s.FIRST_PARTY_WON_BUY_BOX
      , s.THIRD_PARTY_SELLER
      , s.PRIME_EXCLUSIVE
      , s.PROMO_TYPE
      , NULL::BOOLEAN                        AS ADD_ON_ITEM           -- LOST in new schema
      , NULL::VARCHAR                        AS MATCH_TYPE            -- LOST in new schema
      , FALSE                                AS IS_DELETED            -- use PSA_DELETE_IND
      , s.PSA_LOAD_DTS
      , s.PSA_RECORD_SOURCE
      , s.PSA_DELETE_IND
    FROM SRC_S s
    LEFT JOIN SRC_DD dd ON s.DIM_DATE_KEY            = dd.DIM_DATE_KEY
    LEFT JOIN SRC_AP ap ON s.DIM_ACCOUNT_PRODUCT_KEY = ap.DIM_ACCOUNT_PRODUCT_KEY
)
, LOGIC_R AS (
    SELECT
        COALESCE(NULLIF(TRIM(NAME),''),'-1') AS RETAILER_BK
      , DIM_RETAILER_KEY                     AS R_retailer_id
    FROM SRC_R
)
, LOGIC_A AS (
    SELECT BKCC, REC_SRC FROM SRC_A
)
LOAD_DTS note: The old UPDATED_AT was TEXT — the new is TIMESTAMP_NTZ. The CONVERT_TIMEZONE('UTC', ...) call is unchanged but no ::TEXT cast is needed on UPDATED_AT.
FILTER_a rec_src note: The existing FILTER_a predicate WHERE rec_src = 'US.PROFITERO_FIBERON.PRICING_AVAILABILITY_HISTORY' must be updated to the new REC_SRC value — see REC_SRC section below.

13. Data Continuity & Historical Data Risks

RiskSeverityDetailMitigation
Historical load gap Critical The new profitero_share_* schemas are a data product share. Verify with Profitero whether historical data (pre-share date) will be backfilled. If not, lsat_price_availability__profitero will have a gap between last old-source load and first new-source load. Confirm backfill scope with Profitero vendor before cutover date.
COMPETITIVE_PRODUCT_BK continuity Critical Old COMPETITIVE_PRODUCT_BK derived from products.ID (natural integer). New DIM_RETAILER_PRODUCT_KEY is a different surrogate. If ID values are not the same, existing hub records will not match new ones → duplicate hub entries. Verify whether DIM_RETAILER_PRODUCT has a natural ID column that matches old products.ID. If not, a full-refresh of hub + sats may be required.
PRODUCT_BK continuity (price availability) High Old PRODUCT_BK derived from CUSTOMER_PRODUCT_ID. New equivalent is DIM_ACCOUNT_PRODUCT.ACCOUNT_PRODUCT_ID. If the Profitero account product IDs changed between API versions, hub records will not match. Run the CSV comparison query SELECT 'old', CUSTOMER_PRODUCT_ID FROM price_availability_history UNION SELECT 'new', ACCOUNT_PRODUCT_ID FROM DIM_ACCOUNT_PRODUCT to verify value overlap.
MATCH_TYPE data loss High Exists in lsat_price_availability__profitero — all new records will have NULL MATCH_TYPE. If any downstream model filters or joins on MATCH_TYPE, results will break silently. Search all downstream models (pb_, pit_, dim_, fact_, im_) for MATCH_TYPE references before accepting NULL values.
ADD_ON_ITEM data loss Medium Same as MATCH_TYPE — will be NULL for all new records. Audit downstream before accepting.
Incremental model re-seed Medium If new schema data starts from a different historical baseline, incremental raw vault tables may need --full-refresh after migration. Plan a maintenance window for full-refresh of affected incremental models.
